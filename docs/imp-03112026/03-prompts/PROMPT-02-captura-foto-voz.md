# PROMPT-02 — Capture by photo and voice, incl. Fuel Express (P2, P2a, P9)

Claude Code, Car Guy repo, branch `imp-03112026`. Read `BRIEF.md`, ADR-66/67/75, **SPEC-B (incl. §B7 Fuel Express)**, `docs/imp-03112026/ai-workflow-map.md`, and the SGC reference for `leer-recibo` (read-only). Nothing waits; log defaults.

## Steps
1. **`cg-ai-read`** (kinds `fuel_receipt`, `pump`, `odometer`, `invoice`, `part_label` — the SPEC-C/D/G kinds come in their phases but build the dispatcher so a kind = schema + prompt + post-validator in one registry file): forced tool use, per-field confidence, `unreadable`, image validation (≤ 4 images, mime, size), gateway from PROMPT-01, usage row. Port the RD receipt/invoice rules from SGC's prompts (RNC/NCF formats, RD$, thousands separators), keep them in Spanish, make outputs strictly typed.
2. **Client capture components**: `components/ai/CaptureButton.tsx` (uses `useAiStatus`, camera/gallery via the ADR-59 permission registry and `PhotoPicker`, compress per SPEC-B §B2, web paste/drop hooks), `AiFieldMark` (the "AI" mark + low-confidence outline), a `useAiDraft()` store that passes a prefill to the existing screens.
3. **Wire the workflows** (SPEC-B §B2): `FillUpForm` (receipt + odometer-photo, keeping the duplicate check and the review sheet, adding the deterministic sanity checks: odometer below last, gallons×price vs total > 3 %), `servicio/nuevo` (invoice → items table, shop contact match-or-create, total, warranty parse, `invoice` media), `gasto/nuevo`, `/odometro`.
3b. **Fuel Express (P9, SPEC-B §B7)** — the headline of this phase. Add kind `fuel_express` to the `cg-ai-read` registry (two images in one call, per-image classification, merged object, per-field confidence). Build `app/carga/express.tsx` (camera-first flow: dashboard photo, receipt photo, either order, either skippable) and the **single "Confirmar carga" screen** (one summary card, edit in place, one big **Confirmar**; compact when everything is confident, expands only the field that fails a check). Reuse `FillUpForm`'s save path, `fillupDedupe.ts` and the sanity checks (odometer below last, gallons×price vs total > 3 %, unit mismatch mi/km, implausible price, date too old). Wire it as the primary action behind Hoy's **Cargar gasolina** (the manual form stays one tap away: "Llenarlo a mano"). Offline: `ai_queue` (schema v13, additive; Dexie-free — use the app's SQLite layer), queue processing on reconnect, local notification "Tu carga está lista para confirmar", 7-day expiry. Strip EXIF GPS before upload. Round-trip test covers every field Fuel Express can fill. Eval set `fuel_express` (synthetic dashboard+receipt pairs). Playwright: two fixture photos → Confirmar → record exists with `invoice` media; airplane-mode test for the queue.
4. **Voice**: `cg-stt` (SPEC-A §A3 provider rules; ≤ 30 s; verify Azure's accepted containers in the docs and, if Safari's `audio/mp4` or Chrome's `webm/opus` is not accepted by the chosen path, convert client-side to 16 kHz mono WAV) and `cg-ai-intent` (SPEC-B §B3, closed target list, ambiguity returns `choices`). Client: `VoiceButton` + transcript sheet, native recording with the Expo 57 audio module (read its docs first), web `MediaRecorder`. Add `microphone` to the **ADR-59 permission registry** (primer text, denied/blocked states, "how to enable" steps, web + Android + iOS PWA), update `app.json` (Android `RECORD_AUDIO`, iOS `NSMicrophoneUsageDescription` text in es/en) and **`vercel.json` Permissions-Policy → `microphone=(self)`**. Entry points: Herramientas search mic, Inicio quick action "Dictate", form headers.
5. **Round-trip and field tests**: extend the ADR-63 round-trip test with every field an AI read can fill; unit-test the draft store, the sanity checks and the intent→route mapper (table-driven, 30 sentences es-DO).
6. **Evals** (SPEC-B §B5): `evals/ai/run.mjs` + synthetic fixtures + README for real photos; run against the deployed functions; record accuracy in PROGRESS.
7. **Deploy** `cg-ai-read`, `cg-stt`, `cg-ai-intent` to x-core; log. es/en strings; no emoji icons.
8. Verify in a browser (Playwright, mobile + desktop viewport) end to end with a test account: receipt → pre-filled fill-up → save; dictate "eché 12 galones…" → fuel form pre-filled. Typecheck/lint/tests/build green. Commit.

## Acceptance
SPEC-B §B6. Plus SPEC-B §B7 acceptance (two photos, one tap on the happy path). Plus: a failed or `unreadable` read leaves the form exactly as it was; offline shows the reason; nothing is saved without the normal Save; costs per call visible in Admin → Uso y costos.
