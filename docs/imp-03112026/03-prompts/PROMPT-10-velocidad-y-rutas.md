## Steps
1. **Baseline first.** Build the replay harness *before* changing behaviour: extend `tools/gen-drive-gpx.mjs` with ground-truth drives (city stop-go, highway cruise, hard braking, tunnel dropout, urban canyon 30–60 m noise, Android "speed 0 while moving", iOS −1 speed, 1 Hz vs 0.2 Hz) and `__tests__/trips/speed-replay.test.ts` scoring the **current** pipeline (live needle path, saved `stats()`, distance). Record the old numbers (RMSE, top-speed error, distance error, braking lag) in PROGRESS and `docs/imp-03112026/speed-before-after.md`. Confirm I0 facts (SPEC-I) with file:line, including the live-max vs saved-max disagreement.
2. **`lib/trips/speed.ts` SpeedEngine** (SPEC-I §I1): pure TS, no React, no I/O. Input gate; Kalman fusion with adaptive process noise; windowed regression where Doppler is missing; stop hysteresis; sustained top speed (≥ 2 s, accuracy ≤ 20 m); moving vs total average; segment speeds. If `expo-location` exposes speed accuracy use it for the variance, else derive from horizontal accuracy (record which in Decisions).
3. **Replace the parallel implementations**: `reduceLive`/`displayKmh` (needle), `geo.ts stats()` (saved max/avg/distance), map segment colours and anything that computes max/avg speed all call SpeedEngine. Delete the old EMA/median code paths; add the test that **live max === saved max** for the same fix stream. Saved trips store GPS truth; migrate nothing retroactively except an optional "Recalcular" on a trip detail (recomputes from stored points if they exist) — never silently rewrite history.
4. **Calibration** (SPEC-I §I2): schema **v14** local migration (v13 is `ai_queue`, taken by PROMPT-02) + additive cloud `sql/044` (`vehicle.speed_factor numeric default 1`, `vehicle.odo_factor numeric default 1`, check ranges 0.8–1.2, re-runnable, rollback block, local-rls test, `types:gen`, `verify-x-core`); sync columns; add to the ADR-63 round-trip test. UI in the vehicle ficha → Calibración: "Calibrar velocidad" guided flow (steady speed, type the dash value, median factor after ≥ 3 samples), odometer factor suggestion after ≥ 3 intervals ≥ 100 km, setting **Mostrar velocidad: GPS real / como mi tablero** (default GPS real). Plain-Spanish explanation that the dash over-reads on purpose.
5. **Live needle**: fused value with small predictive lead, "estimada" label where Doppler is absent (web/iPhone), 0 only by the hysteresis rule; the trip card shows top speed with its time and "GPS".
6. **Raw-fix recorder** (off by default, Ajustes → Viajes → avanzado): keeps raw fixes of the last N trips and exports GeoJSON/CSV so a real bad trip can be replayed. Add `docs/CALIBRATION-DRIVE.md` (steady 60/80/100 km/h with dash photos or a second phone; fill-up-to-fill-up odometer check).
7. **Route lines** (SPEC-I §I4, P6a): implement `routeFrequency()` in `lib/trips/geojson.ts` (15 m resample, grid-edge key, merge opposite directions, cap 20k edges) with tests; replace the heatmap layer in **both** `HeatMap.tsx` and `HeatMap.web.tsx` (same component API) with the thin line layer: width 0.8 px at z10 → 2.4 px at z16 (+ up to 1 px by log count), amber→orange→red ramp, faint glow underneath (width × 2.5, blur 2–3, opacity 0.18–0.25), round caps/joins, no blobs/casing; legend "pocas veces → muchas veces"; optional tap-to-count. Slim the individual route lines to ~3 px over a 5 px casing, zoom-interpolated, tokenised. Verify light and dark styles. **No heatmap layer may remain.** Update `app/viajes/index.tsx` sampling accordingly (`sampleAlong` no longer needed for this layer).
8. **Screenshots**: Playwright before/after of "Por dónde manejas" at zoom 10/13/16 into `04-tracking/screens/` (take the *before* first).
9. Re-run the replay table; the targets are steady RMSE ≤ 1.5 km/h, accelerating ≤ 3, top speed ±2 km/h, distance ±1.5 %, no spike ever becomes top speed. If a case misses, say which and why — do not tune until it passes by weakening the test.
10. Typecheck/lint/tests/web build green. i18n es/en. Commit.
